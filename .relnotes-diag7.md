## What this build fixes

`2.1.14-diag5` loses the log entirely on the Y9000P ([#198](https://github.com/physicsdolphin/nv-uefi-unlocker/issues/198) secondary finding): `loader.log` stays 0 bytes on every run - tx and readonly alike - and a full-cluster carve finds no log content anywhere, even on the readonly run that completed successfully. The code path explains it: the diag3+ create-commit dance is `CreateReadWrite → Close → Open(ReadWrite) → set_position(EOF)`, and on that firmware the reopen chain **refuses cleanly** - the logger then degrades to console-only for the whole run, so nothing ever enters the file. The same Close/reopen machinery that wedges the Z97-K init window (#122, 4/4 no-signal) fails in a second, cleaner mode on this Lenovo. v2.1.10 and diag2 (no dance: one long-lived handle, flushes, a single Close at handoff) log fine on both machines - which is exactly why they were chosen as the reference.

`2.1.11-diag7` keeps the ladder from diag6 and adds **auto-degrade**: if the reopen after the create-commit returns nothing, the logger recovers at init - nothing has been written yet - by taking a fresh handle and forcing commit level 0 (the v2.1.9 flush-only write path) for the rest of the run. Line 3 of every log names the state it ended up in:

```
BOOT: diag7 log-commit=N (0=v2.1.9 default, 1=+marker Close, 2=+create Close; auto-degrades to 0 if the reopen chain refuses)
```

## Switches (unchanged from diag6)

| File on the stick root | Effect |
|---|---|
| *(none)* | **default**: write + Flush on marker/cadence lines, one long-lived handle, no `Close` (v2.1.9 semantics) |
| `tx-log-commit-lines.txt` | + `Close`/reopen on marker lines |
| `tx-log-commit.txt` | + the create-time `Close` (diag4/5 semantics, with auto-degrade) |
| `tx-no-ident-dump.txt` / `tx-no-early-enum.txt` | skip the identity dumps / the `EARLY:` connect pass |

## What this means for the two open cases

- **Y9000P (#198)**: default or `tx-log-commit.txt` both produce working logs now (the latter via the auto-degrade). Your runs should log like diag2 did - 47-56KB, committed at handoff.
- **Z97-K (#122)**: the default (level 0) avoids the init-window wedge by construction; the ladder round stands as before (empty stick → `tx-log-commit-lines.txt` → `tx-log-commit.txt`, one cold boot per step).

The Close/reopen machinery now has two documented firmware failure modes; level 0 - the path every shipping release used - is the default everywhere and remains the reference.
