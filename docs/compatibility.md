## 路由与证据等级

本工具按芯片家族路由，同族设备共用 Booter/payload 资产。设备 ID 可进入事务路径，不代表该型号已经单独实测。

| 等级 | 含义 |
| --- | --- |
| ✅ | 本工具有实机证据；仅 EFI 成功或仅系统侧验证的情况单独注明 |
| 🟢 | 上游或社区有同链硅验证，不等于本工具逐卡验证 |
| 🟡 | 代码路径存在，完整实机验证待补充 |
| ❌ | 不支持 |

| 家族 | PCI device ID 范围 | 资产选择 |
| --- | --- | --- |
| Turing | `0x1e02..=0x1fff`、`0x2182..=0x21d1` | `tu10x` |
| Ampere GA10x | `0x2200..=0x22ff`、`0x2400..=0x25ff` | `ga102` |
| Ada | `0x2600..=0x28ff` | `ad102` |

支持家族中的移动、工作站、CMP 与魔改卡使用所属家族的路径。GA100（A100 `0x20b0` / `0x20c2`、A30 `0x20f1`）、Hopper 和 Blackwell 不在支持路径中。未单列的同族 ID 继承家族证据等级。

## 验证结论与例外

<a id="device-1"></a>

### AD107 · 4060 Laptop 28e0

本工具全链解锁与 Windows 验证通过。独立平台复现同样确认系统侧状态和 Tensor 性能提升。[#119](https://github.com/physicsdolphin/nv-uefi-unlocker/issues/119) 为第三个独立数据点（同机系 PHN16-71 但 **BIOS V1.20**，驱动 617.42）：三段消融确认**混合模式入口 BAR0/MMIO 全 `0xffffffff` 不可读、NVIDIA GPU Only 直连 13/13 sweep 可读**（显示模式矩阵 Insyde V1.20 样本），TX 全绿、FP16 +49.4% / BF16 +56.9%（组间离散提示热限，散热待查）；SB/BitLocker 先关后复并验证。来源：[实测报告](ada28e0-uefi-report.md)、[#63](https://github.com/physicsdolphin/nv-uefi-unlocker/issues/63)、[#119](https://github.com/physicsdolphin/nv-uefi-unlocker/issues/119)。

### AD107 · 4060 2882 / 4060 Laptop 28a0 / 4050M 28e1

`28a0` 全链与 Windows 性能验证通过（两份独立报告：[#50](https://github.com/physicsdolphin/nv-uefi-unlocker/issues/50) 极光15 与 [#136](https://github.com/physicsdolphin/nv-uefi-unlocker/issues/136) 耀世15Pro——后者为 **v2.1.9 首份同脚本匹配 A/B 全精度谱**：FP16 +81%/BF16 +80%/TF32 +79%/FP8 +85%，FP32/显存/时钟三对照持平，第二套基准交叉差 2%；140 W 薄轻机身下绝对值低 13–15% 属散热包络，每 MHz 效率与 #119 对齐）；`2882` 一手 Windows 实测通过（Win10 22H2 + B760M AMI，首次冷启动即成功，matched A/B：FP16 +57% / BF16 +63% / FP8 +47%，FP16-acc/FP32/INT8 三对照平坦，数值与 ada2882 canary 逐位对齐；解锁后时钟反降 2250MHz 仍 +1.5×——power-wall 限与 4090 侧信道一致）；`28e1` 保留上游硅验证层级。来源：[#50](https://github.com/physicsdolphin/nv-uefi-unlocker/issues/50)、[#124](https://github.com/physicsdolphin/nv-uefi-unlocker/issues/124)、[#136](https://github.com/physicsdolphin/nv-uefi-unlocker/issues/136)。
`28a0` 第三平台（[bailu974 记录](https://github.com/bailu974/nv-uefi-unlocker-on-SecureBoot)，2026-11-08/09）：COLORFIRE MEOW R15 24 / Ryzen 7 7435H / Insyde `1.07.11COLO1`，驱动 576.88（旧驱动跑通）；**Secure Boot 开启**——用该 Insyde 固件的 `Select a UEFI file as trusted for execution`（按文件信任，PK/KEK/db 未动，FAQ 路线 C 首例）；**ESP 驻留**（固件拒建新 `BootXXXX` 回 `err=87`，改写 `Boot0000` + `Boot2001` 兜底，首例）；本地补丁免疫 EC 合成的 `0x03` 幽灵键（卡键家族第二例，FAQ 幽灵按键节）；8192³ BF16 27.20→40.94（+50.5%）/FP16 +49.8%/FP32 平，ssdiag `UNLOCKED`；**附带反例：SB 开启下 ssdiag 的 pmxdrv 实际加载成功**（与"必然被拒"的默认预期矛盾，机理未知，见 FAQ）。

**`28a0` 第四平台 + 首个 FP8 全谱同机 A/B + 运行期掉锁程序层解法（[D#229](https://github.com/physicsdolphin/nv-uefi-unlocker/discussions/229)，2026-11-11）**：MECHREVO 旷世 G16（GM6PG0Q，i5-13500H，VBIOS `95.07.16.80.e0`，驱动 616.92 LEGACY mode，Win11 26H2 26300.9711），官方 v2.1.11（`-UtilsSource local` 本地 DriverStore 取 GSP），上游 `bench_gemm.py` 7 case×2 pass：TF32 +81%/FP16 +77~84%/BF16 +78~87%/**FP8 e4m3 58.63→103.24（1.76×）**，FP32 对照 −0.3% 持平，B 组多处 `POWER-CAPPED`（113–120 W）；正确性 vs FP64 与锁态同量级。**运行期掉锁（非引导问题）在同报内现场记录并解决**：bench 后空闲 ~2 min 即被 RTD3/D3cold 撤电抹锁（`CANARY: cleared`，混合输出内屏走 Iris Xe、Modern Standby-only、ASPM 最大节省）→ **常驻 CUDA context 保活（计划任务 SYSTEM 开机自启，5 s 真 kernel 提交）+ ASPM 关**后同引导 6/6 采样近 12 min 全 `HELD`/`UNLOCKED`，`nvidia-smi` 仍 P8/1.5 W——混合拓扑零改动、不接显示器（已入 FAQ #relock "给 dGPU 制造引用"项，该轶事的首个 Windows 实证）；边界如实：未做停保活因果对照、Modern Standby/合盖未测、交棒→驱动接管空窗用户态无解。限制：跨两趟开机的准 A/B（FP32 对照补可信）、无端到端应用测量。另录内置 1 GiB ESP 型分区免 U 盘部署（详见社区记录免 U 盘节）。

机理上：**是否发生回锁取决于平台侧谁在 bind 前重跑 devinit**——笔记本上是 MUX controller 与 EC 的厂商行为设计，桌面老固件上是 CSM 时代固件的 legacy-VGA/初始化路径；这些路径都会在自己认为该复位的时候重跑 devinit（把 FEAT 块推回厂值），且都不在驱动控制范围内。待验证推论：对笔记本用户"升级驱动"只是换一条回锁路径，不是修复（直连平台 617.42 即可存活）；桌面侧不再需要以驱动版本为闸。`#99` 的 PF FLR 曾记为同族的另一个观测形态（复位型）、与回锁型分桶；2026-11-12 的同卡 A/B 把两桶接上了——**是我们交棒时的重锁写诱发了驱动侧的 PF FLR**，门开交棒后同一驱动即无事件。
