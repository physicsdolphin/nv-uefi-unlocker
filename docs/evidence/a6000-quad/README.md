# 四张 A6000（GA102 2230，同机同批）fuserow 全量对比（owner 采集，2026-11-28）

环境：Ubuntu 24.04.5 / kernel 6.8 / 驱动 580.178.04 GSP active / SB off /
Xeon Gold 6454S / Lenovo 工作站；diag-unlock.py（per-die IFF 界修复后版本），
4 卡全量 576 行 ×2 pass 全绿（锁存验证、地址恢复）。SUBSYS 全部 1459:10de
（Gigabyte 同批）。

## 逐行 diff 结构（6 对两两对比，每对 ~109-122 行差异 / 576 行）

| 区 | 差异 | 定性 |
|---|---|---|
| **0x0-0x7**（加密头） | **0** | 四卡逐位相同（同 die 同 SKU 模板） |
| **0x8/0x9, 0xc/0xd, 0xe/0xf, 0x12/0x13, 0x2e**（SKU 头成对行） | 每对有差 | **每卡微差**——binning/微码 patch 级数据（0x8 对差异在高位 nibble，0xc/0xd 全 16 位不同，0x2e 差在 bit31/29——非 floorsweep 形状） |
| **0x14-0x2b**（floorsweep/SKU 区） | **0** | 四卡相同 = **同 SKU 零 floorsweep 差异**（TPC STATUS 面全零一致） |
| **0x30-0x54**（随机密钥区） | ~29 | **每卡唯一**（设备身份材料，符合"二次加密"既有分类） |
| **0x55-0x204**（中段池+杂项数据） | ~86 | 混合：0x55/0x63 小数值差（配置位）+ 0x5e-0x62 随机差 + **0xed-0x132 段为逐卡不同的"位错位"形（同一数据模式在不同卡上出现在不同行偏移）**——疑似每卡唯一的 devinit 脚本变体或链表式结构 |
| **0x206-0x23f**（IFF op 池，58 行） | **0** | **四卡逐位相同**——池是 die/SKU 模板，零每卡差异 |

## 判读

1. **同型号差异图谱首次成图**：每卡 ~110-120 行差异（19-21%），但**结构区
   （加密头、floorsweep、IFF 池）零差异**——全部差异落在 SKU 微码头、
   随机密钥、中段每卡数据。**"同型号 fuse 差异 = 每卡身份+微 binning，
   非 SKU 功能差异"**——同批同型号卡的 fuse 功能面完全一致。
2. **IFF op 池 4×0 差异**直接证实：池是 die+SKU 模板（与五卡文法分析的
   "跨 die 结构锁"自洽）——A6000 的 GA102 池应与 3090 的 GA102 池
   **逐位可比**（SKU 差异不进池）。**待办：拉 3090 池对比**（专业卡 vs
   消费卡同 die 的池差异 = SKU 功能差异的直接测量）。
3. **0xed-0x132 的"错位"形态是新观察**：四张卡的同一数据模式出现在
   不同的行偏移上——像是每卡的链表/结构区起点不同。定性开放（登记）。
4. FEAT_SS0/SS1 四卡各不相同（0x76260022/0x57126032/0x14700000/0x45352000，
   SS1=2/6/7/3）——**出厂钳制每卡不同**（binning 特性的又一证据）；FBPA_PLM
   全部 0xffffff0f（专业卡深锁形，与消费 0xffffffcf 对照）。
5. 全部 PLM 面（FEAT_PLM 0xffffff8f、FBPA_PLM 0xffffff0f、XVE 族 8f/cf）
   四卡一致——**权限模板零每卡差异**。
