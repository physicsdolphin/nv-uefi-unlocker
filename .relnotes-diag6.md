## Why this build exists

The three diag5 cold boots on #122 died one layer above where diag5 was aimed: the log dirent was freshly created every round, yet **zero bytes, zero FAT clusters, zero string hits and no display signal** - the run ends inside the window that opens at the log's create and closes before the first line reaches the medium. The FWSEC judgement table (PROM/GSP/IMEM/HALT) is not reachable on that board until this window is crossed.

The suspect is the **Close-based commit itself**. diag3/4/5 always Close (once for the create, once per marker line); v2.1.9 and diag2 never Close at all, and both boards sedimented 157-239 lines per run on those builds. So this build makes the Close a **stick switch and defaults it OFF** - default behaviour is the v2.1.9/diag2 write path, byte for byte.

## Switches

| File on the stick root | Effect |
|---|---|
| *(none)* | **default**: `Write` + Flush on marker/cadence lines, one long-lived handle, no `Close` ever (v2.1.9 path) |
| `tx-log-commit-lines.txt` | + `Close`/reopen on marker lines (diag3/4/5 commit half) |
| `tx-log-commit.txt` | + the create-time `Close` as well (full diag4/5 behaviour) |
| `tx-no-ident-dump.txt` | skip the `DIAG-CONSOLE-*`/`DIAG-BOOTVOL` dumps |
| `tx-no-early-enum.txt` | skip the pre-enumeration `EARLY:` connect pass |

Line 3 (`BOOT: diag6 switches log-commit=N ...`) records what was read, so every log names its own configuration. With commits off the dirent stays stale and the file reads 0 bytes on a crash - **the FAT cluster carve is the reader**, exactly as with v2.1.9.

## The pre-log probes are themselves a probe

`tx-log-commit*` is read *before* the log file exists. If a run dies inside those two directory probes there is **no fresh dirent at all** - that distinguishes "died before the create" from "died after the create", which the media alone could not.

## Run order (cold boot each, one round each, stop when the log comes back)

1. **nothing on the stick** - if logs sediment again, the Close is the regression; go to 4.
2. still nothing, but the dirent is *not* fresh → died in the pre-log probes.
3. still nothing with a fresh dirent → not the Close; add `tx-no-ident-dump.txt`, then `tx-no-early-enum.txt`, one per cold boot. Report which one, if any, restores the log.
4. if the log comes back: keep the level that works for the transaction runs, and add `tx-log-commit-lines.txt` on a later cold boot to see whether the per-line commit alone is survivable.

Report per round: whether `\loader.log` is fresh (dirent timestamp), its size, the first and last line (carve if 0 bytes), whether the `BOOT: diag6 switches` line is present, and the total elapsed between the first and last timestamp. The screen is expected to stay dark on this board - it is not a verdict.
